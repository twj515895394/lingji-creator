# PRD：SceneForge Draft Refinement（带补充意见的整阶段草案优化）

## 问题陈述

当前 SceneForge 已支持：

1. 运行阶段生成草案
2. 重新生成整版草案
3. 提交草案到产物库
4. 对已提交内容请求修订

但在一个更高频的中间场景里仍然缺口明显：用户对当前草案“大体满意，但想补几条指令继续优化”。例如“保留当前结构，但加强镜头语言”“保持这版节奏，结尾再狠一点”“按 Pixar-like 风格收紧动作表演”。如果没有这个能力，用户只能整版盲重跑、手工改 Markdown，或者先提交再走 revision，都会让草案迭代成本偏高。

## 解决方案

建立一个独立的 Draft Refinement 文档包，定义：

1. 如何基于“当前草案 + 当前阶段上下文 + 用户一次性补充意见”重新生成整阶段草案。
2. 哪些阶段支持这项能力，以及它与普通 Run / Regenerate / Request Revision 的边界。
3. 草案生成后是否必须人工提交，如何由阶段定义固定配置。
4. Studio、runner 输入、验收与测试口径。

## 用户故事

1. 作为创作者，我想针对当前草案补充几条具体意见，再生成一版新草案，而不是完全盲重跑。
2. 作为创作者，我想让补充意见只影响这一次生成，以便不污染项目长期状态。
3. 作为创作者，我想在所有支持草案生成的阶段都使用同一套补充优化心智，而不是每个阶段都重新学一遍。
4. 作为创作者，我想知道这次补充优化生成后，是否需要我手动确认再落盘，以便避免误操作。
5. 作为维护者，我想把“补充优化”和“重新生成”“请求修订”分开，以便 UI 语义与状态机边界保持清晰。
6. 作为维护者，我想把是否必须人工提交定义为阶段固定策略，以便避免项目级和运行时开关把产品语义变复杂。

## 实现决策

- 首版只做“整阶段补充优化”，不做分字段或分段精修。
- 用户补充意见是一次性临时指令，不写入项目长期状态。
- 该能力适配所有支持草案生成的阶段，不做单阶段特判。
- “生成后是否必须人工提交”由阶段定义固定配置，不做项目级或运行时覆盖。
- 补充优化生成出来的仍然是新草案；若阶段配置要求人工确认，则用户仍需提交草案后才落盘。

## 测试决策

- runner 输入测试：当前草案、阶段上下文与一次性补充意见能正确组装。
- 阶段策略测试：不同阶段的“必须人工提交 / 可直接落盘”策略可被稳定读取。
- UI 测试：普通运行、重新生成、补充优化、请求修订四类动作边界清晰。
- 真机验收：至少验证一个 core 阶段和一个 support 阶段的补充优化路径。

## 超出范围

- 分字段补充优化。
- 分段或局部细粒度编辑。
- 补充意见的长期持久化或可复用模板。
- 项目级覆盖阶段落盘策略。
- 运行时临时切换“先审阅 / 直接落盘”。
