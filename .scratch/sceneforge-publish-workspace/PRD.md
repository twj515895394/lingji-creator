# PRD：SceneForge Publish Stage 工作区

## 问题陈述

当前 `publish` 在 SceneForge 阶段体系中已存在，但仍属于占位状态。维护者无法回答：publish 阶段到底消费哪些上游产物、产出什么、与 export 的边界在哪。缺少这层定义，后续代理很容易把 publish 误做成“自动发布平台集成”，或者继续长期空置。

## 解决方案

建立一个独立的 publish 工作区文档包，先把它定义清楚：

1. publish 阶段的输入、输出与工作区职责。
2. publish 与 export、Prompt Pack 导出的边界。
3. 首版是否需要 Stage Pack，以及 Pack 产物应该是什么。
4. 自动化与人工验收口径。

## 用户故事

1. 作为创作者，我想在生成完成后有一个 publish 阶段整理发布素材，以便在真正对外发布前做最后检查。
2. 作为创作者，我想知道 publish 用的是哪些上游产物，以便确认是否可以进入发布准备。
3. 作为创作者，我想把发布描述、发布检查项或平台适配信息组织成结构化产物，以便后续复用。
4. 作为维护者，我想把 publish 和 export 分开，以便不把导出误做成发布集成。
5. 作为维护者，我想让 publish 首版保持轻量，以便先明确边界再决定是否接第三方平台。

## 实现决策

- publish 首版定位为“发布准备工作区”。
- export 继续负责 Prompt Pack 导出，不吸收 publish 职责。
- publish 是否使用 Direct LLM / manual_submit / ACP 由后续实施时再决定，但本包先定义工作区与产物契约。
- 首版不做任何外部平台 API 集成。

## 测试决策

- 文档层确认输入、输出、边界和验收步骤齐全。
- 后续实现时至少有一个工作区显示测试和一个产物契约测试。

## 超出范围

- 自动上传到抖音、B 站、YouTube 等。
- 发布日历与排期系统。
- 媒体资产二次渲染。

## 进一步说明

- 本包是明确后置项的前置设计，不代表本轮立即实现。
