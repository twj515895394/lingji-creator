# 关键帧、缩略图与视频预览可信度闭环

Type: AFK

## 父问题

`.scratch/sceneforge-remix-ui-recovery/PRD.md`

## 要构建什么

建立 Remix 媒体预览可信度闭环，确保视频预览、关键帧和资产缩略图都遵循：

- 能显示真实内容就显示真实内容
- 不能显示就明确报错
- “已完成”必须与实际文件可读和前端可加载绑定

端到端行为：

- 资产封面按既定优先级选择真实帧。
- 关键帧加载失败时显示明确错误与修复入口。
- 视频路径不可读或缩略图回退失败时，页面给出可理解错误反馈。
- 页面可感知媒体校验结果与异常计数，而不是只显示“看起来像成功”的封面。

## 实施约束

- 实现必须严格遵循 `docs/sceneforge2.0/technical-solutions/05-remix-media-preview-keyframe-and-thumbnail-reliability.md`。
- 不能再用暗色占位伪装成成功。
- 关键帧与缩略图状态必须建立在真实文件校验之上。

## 验收标准

- [ ] 资产卡封面优先使用真实关键帧，其次视频首帧，最后才是明确 fallback
- [ ] 关键帧加载失败时显示明确错误，而不是暗色空块
- [ ] “关键帧已完成”与图片路径存在、文件可读绑定
- [ ] 源视频路径不可读时，预览区显示明确错误和修复建议
- [ ] 存在 `validateSourceAssetMedia` 或等价媒体校验入口，供页面加载时消费
- [ ] 资产卡或详情区可表达关键帧异常计数，例如“9 张关键帧 · 2 张异常”
- [ ] 缩略图与关键帧在刷新或重进项目后仍可稳定加载

## Review Checklist

- [ ] 后端存在关键帧 / 缩略图校验或等价可靠判断
- [ ] Renderer 不直接依赖脆弱的绝对路径字符串
- [ ] fallback 优先级与 05 方案一致
- [ ] 媒体校验结果有稳定的前后端契约，不是组件内临时猜测
- [ ] 失败状态可进入处理链继续修复，而不是 UI 黑洞

## 测试与验证

- [ ] 覆盖关键帧缺失、视频缺失、缩略图回退三类场景
- [ ] 手动验证：真实图片、错误 UI、fallback 优先级都符合预期
