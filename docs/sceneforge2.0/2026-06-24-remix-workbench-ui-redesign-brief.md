## 1. 文档目的

这份文档不是在讨论“补几个样式细节”，而是在重新定义：

**Remix 应该长成什么样，才像一个专业桌面创作工作台，而不是深色营销页拼出来的概念稿。**

本 Brief 解决的问题是：

1. 布局秩序
2. 信息层级
3. 字体与排版系统
4. 组件角色边界
5. 工具工作台的整体气质

它不负责先救可用性。  
可用性先由 `P0 workflow recovery plan` 处理。  
本 Brief 的前提是：主流程已经恢复真实性，接下来要让整个工作台变得清晰、整洁、专业、可信。

---

## 2. 当前 UI 失败的根因

当前 Remix UI 最大的问题不是某个按钮丑，而是 **界面类别判断错了**。

它目前更像：

- 深色品牌展示页
- 设计感概念稿
- 面板式运营后台

而不像：

- 专业桌面创作工具
- 视频编辑工作台
- 高密度但可读的素材处理界面

根因包括：

1. 过度依赖大圆角、金色渐变、柔光边框、空洞大面板
2. 中间主工作区没有成为视觉中心
3. 英文大写眉题和中文内容节奏不统一
4. 卡片太多、块太多、说明文太多，工具味不够
5. 组件都像展示卡，不像工作控件

---

## 3. 设计读法

将 Remix 读作：

**桌面端视频资产处理与 AI 二创预处理工作台，面向高频创作者，视觉语言应靠近专业剪辑器和内容生产工具，而不是营销页或概念化大屏。**

参考优先级：

1. 剪映桌面版的工作区秩序
2. 灵机剪影现有编辑器中的预览 / 时间线 / Inspector 心智
3. SceneForge 当前设计中可复用的产品语言

不参考的方向：

1. Awwwards 风格 landing page
2. 营销型深色大卡片布局
3. 过度装饰化的 cinematic 面板语言

---

## 4. 重设计目标

### 4.1 目标气质

重设计后的 Remix 应给人这几种感受：

1. 清楚
2. 稳定
3. 专业
4. 可验证
5. 高效

不追求：

1. 强装饰感
2. “高级感”先行
3. 大量视觉特效
4. 靠深色渐变制造科技感

### 4.2 用户第一眼应该感受到什么

用户打开后，应该第一眼就明白：

1. 当前页面是什么
2. 中间最重要的工作区在哪里
3. 左边是流程还是素材导航
4. 右边是当前上下文还是参数区
5. 下一步主要操作是什么

如果第一眼还需要读很多说明文，说明布局失败。

---

## 5. 页面级重设计方向

### 5.1 Asset Library

定位：

- 媒体资产浏览与分发页

核心目标：

- 让用户快速识别素材
- 快速判断资产状态
- 快速决定“继续处理”还是“发起二创”

布局方向：

- 左栏：轻量筛选和分类
- 中间：以真实缩略图为核心的资产列表
- 右栏：选中资产摘要与单一主动作

视觉要求：

- 资产卡优先呈现素材，不优先呈现装饰
- 卡片信息控制在“看一眼能扫完”的范围
- 避免大段说明文占据卡片主体

### 5.2 Asset Processing Workspace

定位：

- 视频资产处理页，不是信息看板页

核心目标：

- 让中间工作区成为绝对主角

布局方向：

- 左栏：流程步骤导航
- 中间：视频画布 + 时间轴/结果验证区
- 右栏：当前步骤必要上下文

视觉要求：

- 中间区必须最大、最清楚、最像真的工作区
- 左右两栏降低存在感，不得抢戏
- 表格和说明文退到辅助层

### 5.3 Creation Workspace

虽然本轮不优先重做，但方向需要提前锁定：

- 沿用“中间创作区 + 右侧参数 / 审阅区”的工具工作台逻辑
- 不能退回大卡片说明文堆叠模式

## 6. 布局系统

### 6.1 全局布局原则

必须从“卡片集合”思维转向“工作区骨架”思维。

推荐骨架：

```text
顶部：页面身份 + 项目上下文 + 关键动作
左侧：流程导航 / 筛选导航
中间：主工作区
右侧：Inspector / 摘要 / 参数
底部或中下：时间轴 / 结果列表 / 验证区
```

禁用模式：

```text
大 Hero 卡
+ 大说明文
+ 指标卡
+ 预览占位框
+ 右侧复读型摘要卡
```

### 6.2 面板重量分配

面板视觉重量排序应为：

1. 中间主工作区
2. 当前结果验证区
3. 右侧当前上下文
4. 左侧导航

不允许：

- 左栏和右栏比中间区更显眼
- 中间区长期大面积留白
- 信息密度都堆在边缘

### 6.3 页面顶部

当前很多页面顶部像“标题板 + 说明文板”。

重设计后，顶部应承担：

1. 页面身份
2. 当前资产/项目上下文
3. 一个主动作

顶部不应承担：

1. 大段产品理念解释
2. 反复介绍 `Source Asset` / `Variant` 概念
3. 大量指标卡堆叠

---

## 7. 排版系统

### 7.1 总原则

先建立节奏，再谈字体。

当前问题不是“没换对字体”，而是没有统一的排版角色体系。

### 7.2 建议层级

建议至少定义以下文字角色：

1. 页面标题
2. 区块标题
3. 主工作区标签
4. 正文说明
5. 辅助说明
6. 指标数字
7. 标签 / 状态 / Badge

约束原则：

- 中文优先
- 英文不作为装饰眉题泛滥出现
- 同一屏内不允许同时出现过多接近但不相同的字号

### 7.3 当前必须去掉的排版习惯

1. 大量 10px / 11px 英文大写眉题
2. 中文正文旁边跟着长英文括注
3. 指标标签一律用英文大写
4. 说明文过长过松，像 PRD 贴在界面里

### 7.4 文案形态要求

界面文案必须满足：

1. 先告诉用户现在在哪
2. 再告诉用户能做什么
3. 最后再补解释

不要反过来先写理念说明。

---

## 8. 组件系统方向

### 8.1 卡片

卡片只在真正需要容器边界时使用。

当前问题：

- 几乎所有内容都被卡片化
- 卡片本身压过了内容

重设计方向：

- 资产卡保留，但应更像媒体条目
- 工作区中部减少“展示卡”式容器
- 用分区、留白、细边线替代厚重卡片堆叠

### 8.2 按钮

按钮系统必须重建优先级：

1. 主动作
2. 次动作
3. 轻操作
4. 危险操作

禁止现象：

- 同屏多个看起来差不多重要的按钮
- 每张卡都塞满按钮
- 靠文案长度区分重要性

### 8.3 状态标签

状态标签只表达状态，不承担解释工作。

要求：

- 状态词统一中文
- 颜色语义稳定
- 不再出现 `Pending`、`Segment`、`Variant` 之类混杂标签

### 8.4 表格与列表

表格是辅助验证工具，不是主结果载体。

切片结果的主结果载体应该是：

- 视频验证
- 时间轴联动
- 片段列表与媒体联动

不是冷冰冰的摘要表先行。

---

## 9. 视觉风格约束

### 9.1 颜色

方向：

- 降低金色与装饰性渐变的存在感
- 回到更克制的工具型深色体系
- 用单一强调色表达主动作和当前焦点

目标：

- 看起来像工具，不像展示页

### 9.2 圆角

当前圆角偏大，容易把界面推向“柔软营销页”。

方向：

- 整体收紧圆角体系
- 卡片、输入、按钮、媒体区分别定义规则

### 9.3 阴影与边框

方向：

- 减少柔光和大面积“氛围边框”
- 让边界服务信息秩序，而不是服务装饰感

### 9.4 背景

方向：

- 减少大面积放射渐变背景
- 强化工具工作区的静态稳定感

---

## 10. 参考界面拆解

### 10.1 向剪映学习什么

应该学习：

1. 工作区的秩序
2. 主区与侧栏的权重分配
3. 素材、预览、参数、时间轴的职责清晰
4. 少解释，多反馈

不需要照搬：

1. 图标风格
2. 每一个布局细节
3. 品牌色

### 10.2 向现有灵机剪影编辑器学习什么

应该复用：

1. 媒体预览是核心工作区的思路
2. 时间线不是装饰，是验证与编辑主结构
3. Inspector 是辅助区，不是主叙事区

---

## 11. 重设计后的成功标准

如果 UI 重设计是成功的，用户应当能做到：

1. 不读长说明文，也知道当前页面职责
2. 3 秒内找到主工作区
3. 3 秒内找到当前主动作
4. 通过页面结构自然理解流程，而不是靠培训理解
5. 第一反应是“这是工具”，不是“这是概念稿”

## 13. 一句话结论

Remix 的 UI 重设计目标，不是做得更花，而是 **把它从“深色概念面板”拉回“专业桌面创作工具工作台”。**
