## 1. 文档目的

这份文档不做“大而全的重新设计”，只做一件事：

**把 Remix 从“看起来像工作台、实际上不可验证”的状态，拉回到“至少主流程可信可用”的状态。**

这里的 P0 恢复，不追求第一时间变美，而追求第一时间回答 5 个核心问题：

1. 用户导入的是不是正确素材
2. 当前处于哪个页面层级
3. 当前点击的动作有没有真的执行
4. 切片结果到底是什么
5. 下一步应该点哪里

如果这 5 个问题不能稳定回答，Remix 就仍然不具备交付条件。

---

## 2. 与旧计划的关系

本方案不是替代原 `development plan`，而是对其做 **P0 纠偏覆盖**。

保留的旧假设：

- `Asset Library -> Asset Processing Workspace -> Creation Workspace` 三段式结构是对的
- `资产先入库，创作再引用` 的产品心智是对的
- `Source Asset` 和 `Variant` 的对象拆分是对的

被事实证伪、需要纠偏的旧假设：

1. “只要先把三栏工作台和阶段按钮做出来，用户就能理解流程”
2. “预览区可以先是轻量信息板，后续再补强”
3. “切片结果先用表格和块状 segment 展示即可”
4. “资产卡片先用封面占位与指标卡，也能表达资产可信度”

本方案的结论是：

- 三段式结构保留
- 但 **Asset Processing Workspace** 必须先恢复成真实可验证工作区
- 不能再把“静态样式壳 + 弱反馈摘要”当作主流程闭环

## 3. P0 恢复目标

### 3.1 总体目标

用户从首页进入 Remix 后，必须能顺畅完成这条链路：

```text
首页进入 Remix
→ 选择项目目录
→ 看到真实资产列表
→ 打开某份资产
→ 在处理页看到真实视频
→ 运行切片
→ 通过视频和时间轴验证切片结果
→ 保存入库
→ 回到资产库并看到明确状态变化
```

### 3.2 最小成功标准

只要满足以下标准，就算 P0 恢复成功：

1. 进入 Remix 后不会停留在“像是加载完了、但用户不知道当前在哪”的状态
2. 资产卡片能让用户一眼确认素材身份
3. 处理页中间区域是“真实视频工作区”，不是占位面板
4. 切片结果能与视频播放位置建立联动
5. 处理动作存在可感知的开始、进行中、完成、失败反馈
6. 保存入库前后，页面身份和资产状态明确

---

## 4. 恢复原则

### 4.1 先恢复真实性，再恢复美观

任何“看起来像”的区域，必须优先变成“真的能做”。

优先级：

```text
真实视频 > 美观占位
真实时间轴 > 漂亮块状条
明确状态反馈 > 柔和装饰卡片
单一主动作 > 多个差不多的按钮
```

### 4.2 中间工作区优先

Asset Processing Workspace 的中间区域必须重新成为主角。

左栏负责流程导航，右栏负责当前上下文和参数摘要，中间区域负责：

- 看视频
- 验证结果
- 完成主要操作

### 4.3 一屏只表达一个主任务

每个页面层级只允许一个主叙事：

- 资产库：选素材，决定下一步
- 处理页：处理当前资产并验证结果
- 二创页：基于已入库资产做变体创作

不能让一个页面同时承担“导入、处理、理解、发起创作、解释概念”五种职责。

### 4.4 状态必须可验证

所有阶段状态都必须能被用户验证，而不是只靠文字说明。

例如：

- `切片完成` 必须能对应到时间轴和视频段落
- `关键帧提取完成` 必须能看到实际关键帧
- `保存入库` 必须能反映到资产库状态和可发起二创能力

## 5. P0 问题对应恢复方案

### 5.1 问题：没有可信的视频预览与播放验证区

恢复目标：

把中间的 `Source Preview` 从装饰面板升级为真实的媒体工作区。

目标状态：

- 用户能看到真实导入视频画面
- 能播放 / 暂停
- 能看到当前时间
- 能看到总时长
- 能通过切片结果定位到视频中的对应区间
- 当前选中的 segment 与播放位置可以互相联动

界面原则：

- 中间区域上半部分为视频画布
- 下半部分为可操作的切片时间轴或段落轨
- 表格退为辅助区，不再承担主要验证职责

明确不再接受的状态：

- 只有一个 `Source Preview` 深色框
- 没有真实视频画面
- 切片结果只靠块状列表和表格表示

验收标准：

1. 任意一份资产进入处理页后，用户能确认自己看到的是那条视频
2. 点击某个 segment，视频能跳转到对应位置
3. 播放视频时，当前 segment 会同步高亮

---

### 5.2 问题：切片动作与结果没有强反馈闭环

恢复目标：

把“运行切片”从单点按钮动作，变成“请求 -> 处理中 -> 输出 -> 验证”的完整链路。

目标状态：

- 用户点击切片后，知道系统已开始执行
- 处理中期间，用户知道正在处理当前资产的哪一项工作
- 完成后，用户知道新增了哪些结果
- 如果失败，用户能看到失败原因和建议重试入口

界面原则：

- 在主工作区显式展示当前任务状态，不把反馈藏在按钮文案里
- 切片完成后的首要反馈是“可验证结果”，不是“状态字变了”

建议交互：

```text
点击运行切片
→ 顶部/中部出现“正在分析镜头边界”
→ 完成后自动聚焦切片轨道和第一条新结果
→ 用户可逐段点选验证
```

验收标准：

1. 用户不需要读很多文案，也能知道切片是否成功
2. 用户可以立即开始核对结果，而不是四处找结果在哪

---

### 5.3 问题：资产库不可信，无法一眼认素材

恢复目标：

让资产库承担“识别素材”的职责，而不是让用户靠长文件名和 ID 识别。

目标状态：

- 资产卡片具备真实缩略图或代表帧
- 资产列表中第一眼就能分辨不同素材
- 右侧详情提供素材级确认信息，而不是只堆元数据

界面原则：

- 资产卡片首先是媒体识别单元，其次才是状态摘要单元
- 卡片的第一信息不是渐变封面，而是真实视觉锚点

建议交互：

- 卡片显示真实封面帧
- Hover 或选中后显示更多摘要
- 详情侧栏用于确认当前资产，不再复读卡片说明文

验收标准：

1. 用户在不读长 ID 的情况下，也能认出素材
2. 用户选中资产后，能立即确认当前右栏信息对应的是哪份素材

---

### 5.4 问题：原片理解区不可读

恢复目标：

把“原片理解”从中间产物浏览区，变成可被创作者消费的决策支持区。

目标状态：

- 用户能先看摘要，再看细节
- 用户能快速识别剧情、动作、梗点和可替换元素
- 分段分析能和 segment 选择产生对应关系

界面原则：

- 禁止大段裸 `pre`
- 先结构化摘要，再展开详细分析
- 文本消费必须与处理动作相邻

验收标准：

1. 用户在 15 秒内能读懂“这条素材的核心可复用点是什么”
2. 用户能基于理解结果继续做人工标注，而不是被文本压住

---

### 5.5 问题：资产库、处理页、二创入口页面身份混乱

恢复目标：

把三个页面层级的职责彻底说清楚，并在 UI 中明确表达。

目标状态：

- 资产库：管理资产，决定下一步
- 处理页：处理当前资产，直到能入库
- 二创页：围绕已入库资产创建和推进 Variant

界面原则：

- 每个页面顶部必须有明确页面身份
- 每个页面只有一个主任务
- “返回上一层”的语义必须清楚，不制造“怎么又回来了”的感受

验收标准：

1. 用户在任意时刻都知道当前在哪一层
2. 用户知道下一步应该点哪个主动作

## 6. 页面级恢复方案

### 6.1 首页进入 Remix

恢复要求：

- 入口行为与 SceneForge 其他入口保持一致的心智
- 目录选择成功后，必须给出明确落点

目标结果：

- 不是“好像进去又没进去”
- 而是“我已经进入某个明确工作区”

必须避免：

- 选择目录后停在一个弱状态壳子里
- 页面没有身份提示

### 6.2 Remix Asset Library

恢复重点：

- 资产列表可信
- 当前选中资产明确
- 下一步动作明确

保留：

- 三栏结构

修正：

- 中间卡片必须优先承担素材识别职责
- 右栏必须减少重复说明文

### 6.3 Source Asset Processing Workspace

恢复重点：

- 变成真实媒体处理页

保留：

- 左侧流程导航

修正：

- 中间区从“信息面板集合”改为“媒体工作区 + 结果验证区”
- 右栏只保留当前步骤必须看的上下文

---

## 7. 需要优先复用的现有能力

为了缩短恢复周期，不建议在 P0 阶段重新发明一套新工作台能力。

优先复用方向：

1. 现有视频预览能力
2. 现有编辑器中的时间轴 / 播放状态 / 预览交互认知
3. 现有 Inspector 的信息组织方式
4. 现有项目打开 / 返回 / 关闭行为约定

原则：

- P0 恢复优先做“借成熟能力把主链拉通”
- 不优先做“为 Remix 单独发明一套更美的但不成熟的交互体系”

---

## 8. P0 恢复后的验收脚本

验收时必须逐步实机验证：

1. 从首页点击 Remix
2. 选择目录
3. 进入资产库
4. 能看到资产真实缩略图或代表帧
5. 进入处理页
6. 中间能看到真实视频
7. 点击运行切片
8. 能看到处理中态
9. 切片完成后能通过视频和时间轴验证
10. 保存入库
11. 返回资产库后，状态变化明确

如果第 6 步和第 9 步不能成立，就不算 P0 恢复成功。

---

## 9. 不在本方案处理范围内

以下内容不属于 P0 恢复范围：

1. 最终视觉风格定稿
2. 组件系统全面重构
3. Variant 管理高级能力
4. Seedance 2.0 提示词工作台优化
5. 大规模术语与品牌语言打磨

这些内容应放到后续的 UI 重设计和实施计划中处理。

## 11. 一句话结论

P0 恢复的核心不是“让 Remix 看起来更像剪映”，而是 **先让它像一个真的可以验证素材和切片结果的工作台。**
