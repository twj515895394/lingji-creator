# Findings

## 2026-06-18

- 现有 `regenerate-revision` 只覆盖“整版重跑”和“已提交后的修订请求”，没有覆盖“用户补充反馈后再生成草案”的中间态。
- 用户已明确首版边界：只做整阶段补充优化；补充意见是一次性临时指令；该能力要适配所有支持草案生成的阶段。
- 用户还明确了另一个独立维度：草案生成后是否必须人工提交，应由阶段定义固定配置，而不是项目级或运行时切换。
- 因此需要新建独立文档包，而不是继续把这部分塞进 `regenerate-revision`。
- 与 `regenerate-revision` 的职责切分应固定为：
  - `regenerate-revision`：整版重跑、已提交后请求修订
  - `draft-refinement`：基于当前草案加一次性反馈继续优化
