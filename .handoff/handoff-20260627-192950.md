## 0. 原片理解核心机制梳理（LLM 调度与数据结构）

### 0.1 编排与 LLM 触发流程 (`RemixUnderstandingOrchestrator`)
在工作台的“原片理解”阶段，点击“生成原片理解”按钮触发。全链路业务流如下：
1. **音频提取**：`RemixAudioExtractionService` 确认视频是否包含音轨，如包含且缺音频，提取出独立 wav 文件并计算 hash。
2. **本地 Whisper ASR 转写**：`RemixTranscriptService` 校验已转写的 PlainText 是否新鲜（基于音频 hash 判断）。若发生改变，调用本地 Whisper 提取 SRT 字幕，并根据镜头切片边界（Time Range）进行台词对齐分段，否则直接复用。
3. **片段级 LLM 结构化分析** (`generateSegment`)：
   - 采用并发队列调起 LLM 客户端（`generateStructured` 接口）。
   - **输入数据**：片段标题、起止毫秒、边界类型（粗粒度/高精/人工等）、首中尾关键帧路径、该段对齐后的 PlainText 台词、前后相邻片段标题上下文。
   - **LLM 系统提示词**：[`REMIX_SEGMENT_UNDERSTANDING_SYSTEM_PROMPT`](../electron/sceneforge/remix/remix-segment-understanding-schema.ts#L312-L320)
   - **输出数据**：单个片段的结构化分析 JSON，写入 `{segmentId}.analysis.json`。
4. **全片故事内容串联（Rollup，本轮新增）**：
   - 串联所有片段的剧情功能（`plotFunction`）、动作（`mainAction`）、台词摘要（`speechSummary`）汇总成详细的数据链。
   - **系统提示词设计**：向 LLM 发送串联 Prompt。要求 LLM 充当“剧情解说大师”，把所有片段的内容和发展脉络有机地串联起来，重新整理成一个连贯的、讲得清清楚楚的整体故事梗概（300字以内），并给出 2~4 条具体的二创方向建议（输出 JSON）。
   - **生成文件**：保存并更新 `original_understanding.json` 与 `source_overview.json`，并自动归档生成面向用户的 Markdown。

### 0.2 生成的相关内容结构（JSON Schema）
- **片段理解 JSON 规范** (`sceneforge-remix-segment-understanding` v1)：
  - `visual`: `{ mainAction }`（动作描述）
  - `camera`: `{ shotSize, movement, colorTone }`（景别、镜头运动与视觉调色）
  - `audio`: `{ speechSummary, hasAudio }`（台词摘要）
  - `story`: `{ plotFunction, conflict, emotion }`（剧情功能、冲突、情绪）
  - `remix`: `{ keepElements[], replaceableElements[], rewriteIdeas[] }`（保留元素、替换元素、改写建议）
  - `videoPrompt`: `{ positivePrompt, negativePrompt, motionPrompt, cameraPrompt, dialoguePrompt }`（可由 AI 视频模型消费的提示词组）
  - `quality`: `{ confidence }`（生成置信度）
- **原始理解汇总 JSON 规范** (`sceneforge-remix-original-understanding` v1)：
  - `overall`: 
    - `summary`: string（AI 全片连贯故事内容解说）
    - `remixPotential`: string[]（AI 二创建议列表）
    - `storyArc`: string（片段剧情功能串联，如 `推进情节 → 推起高潮`）
    - `emotionCurve`: string（情绪曲线串联）
    - `visualStyle` & `highValueSegmentIds`（视觉风格与高价值片段列表）
  - `segmentRefs`: 对应各段分析路径及基本元数据的引用索引。

### 1.2 本轮会话完成的 UI 布局与 AI 优化
1. **工作台 4:6 分层布局重构**：
   - 实现了双层渲染骨架：上半部分（`40vh`/`260px`）置顶固定，左侧显示精简版视频播放，右侧展示步骤文字说明与当前片段台词；下半部分独立滚动操作功能区。
   - **去重 Header**：完全剥离了下半部 6 个功能子面板自带的冗余 H2 标题与 Chip，使具体控件直接顶头渲染，节省了首屏展示空间。
2. **播放器 Compact 变体与比例防裁切**：
   - 针对 Compact 变体优化了播放器外框，剥离了嵌套的双重边框与 padding 堆叠。
   - 将上半部列宽比例调整为 **`42fr 58fr`**（缩窄播放器列），配合 `object-fit: contain`，彻底解决了 16:9 原片视频在不同分辨率下控制条和画面底部被裁剪分割的问题。
3. **极简拖拽 resizer 调节线**：
   - 新增了 `upperHeight`（`200px - 450px`）与 `isDragging` 全局事件处理器，支持用户垂直拖拽。
   - 彻底剥离了主容器上带有 `grid-gap` 的 Grid 混合类，使三个纵向模块回归 Flex 线性排列。拖拽区域退化为一条高对比度、悬浮呈琥珀金色的 **6px 物理分割线**，不占多余上下高度空间。
4. **废除剧情/情绪卡片与故事内容串联（LLM 升级）**：
   - 彻底移除了“原片理解”界面占用大块高度的“剧情线”与“情绪曲线”卡片。
   - 将“全片摘要”卡片重塑为“故事内容”，支持在汇总时自动请求 LLM 串联分析所有片段并输出一篇流畅连贯的故事内容梗概（不再是拼装的流水账）。
   - 将“已完成数”标签（`已完成段数：26/26`）提取到“生成原片理解”按钮的同一行右侧并排，页面极度清爽。
5. **单元测试 Mock 与回归**：
   - 在测试用例中注入了模拟的 `generateStructuredData` 返回值，修复了因为没有配置本地 model.ts 而抛出的 `normalizeBaseUrl` TypeError。
   - 测试通过率：12 passed (12)，`npx tsc --noEmit` 无报错。
