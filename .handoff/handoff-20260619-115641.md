### 2.2 运行态与结果不丢失：从“需要 SSE”改成“会话恢复 + 持久化回显”

用户明确否决了“必须流式 SSE”的方向，最终确认的方案是：

- 不强求流式展示；

- 避免每次回来都要重新运行。

这轮已经围绕这个原则补了阶段运行会话、提交后回显、阶段切换恢复等链路。

### 2.3 Continue / Continue & Run / 提交后锁定与可逆重生成

这块是用户连续反馈最多的一条线。

已确认并实现的原则：

1. **提交草案后，默认视为已确认当前生成结果。**
2. 因此 `运行本阶段` 不应继续保持可点击。
3. 但要给用户“反悔”的口子，所以最终不是永久禁死，而是提供明确的 **撤回并重生成**。
4. 这个逻辑要 **适用于所有阶段**，不是只改某一个核心阶段。

本轮已落实的结果：

- `StageRunPanel` 已支持“提交后锁定 + 撤回并重生成”
- `ScenePrepSupportWorkspace` 已把真实 `currentStatus / revisionNote` 透传给共享运行面板
- 之前 support 阶段“提交后仍然能点运行”的问题已经修掉
