## 用户反馈与本轮决策

本轮新增的关键反馈：

- 原片理解阶段现有 ASR 选择器过丑，希望统一为项目现有组件风格。
- 从 `真实镜头切片` 之后开始，点击任一片段卡片，应驱动顶部预览区跳转并播放该片段，而不是只停留在全片上下文。
- 台词相关能力不能只有“重跑整份原片理解”，需要：
  - 全部片段音频 ASR 重跑
  - 单片段音频 ASR 重跑
  - 且都复用顶部唯一一处 ASR 选择值
- “一键确认所有片段台词”后，仍然会有“已被编辑需要重跑”之类提示，导致阶段无法真正结束。
- SenseVoice 有时会产出 `<|ko|><|EMO_UNKNOWN|><|Speech|>` 这类标签串，不能直接泄露到最终 transcript。

本轮达成的实现策略：

- 顶部 ASR 选择收口为页面级单一状态源，不在其他局部再复制第二套选择器。
- 把“点击片段 -> 预览 seek + play”做成切片后多阶段共用行为。
- 将 transcript 重跑与 understanding 重跑拆开，避免“只想重跑台词却把整份原片理解全部重跑”。
- stale 收口不靠隐藏文案，而是修正 correction / freshness 的语义判定。

## 当前已知边界与注意事项

### 1. 单片段 Whisper 重跑的全局聚合策略是保守实现

当前为了避免“把整体 source transcript 元数据错误回写成 SenseVoice 聚合结果”，做了一个保守边界：

- 只有单片段重跑实际走的是 `SenseVoice` 时，才会自动重建 `segment_audio_asr` 模式下的全局 source transcript 聚合。
- 如果用户把单片段切到 `Whisper` 重跑，只更新该 segment transcript，不自动重建整份 source transcript。

这不是 bug 回退，而是有意识的语义保护。后续如果要增强，需要先明确：

- 单段 Whisper 重跑是否允许局部覆盖整体 transcript
- 覆盖后整体 transcript 的 `engine / mode / warnings / srtStatus` 应该如何表达

### 2. 自动播放依赖浏览器/播放器策略

片段点击后已明确触发 `video.play()`，但是否每次都能真播，仍受浏览器自动播放策略和播放器状态影响。需要真机在 Electron 页面里再验一次交互手感。

### 3. 本轮没有继续扩做更大范围 UI 重构

用户主要表达的是“ASR 选择这块样式太丑”，本轮已改为统一组件并和控制区融合；但如果后续要对整块原片理解顶部工具栏做更系统的视觉重构，建议单开 issue，不要混在 ASR 功能链路里继续膨胀。
