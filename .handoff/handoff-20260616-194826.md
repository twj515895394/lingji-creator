## 核心决策

不要把 `/Users/tangwujun/Documents/trae_projects/scene_forge` 的 v9-dev Web Console 直接搬进来。方向是 Lingji Cut 原生的 SceneForge Studio。

流程执行由程序推进：

- 程序维护阶段状态、Artifact Manifest、Validator、Approval Policy、Stage Context。
- LLM / ACP Agent 只接收程序组装后的规则、模板、上下文和输出契约。
- Agent 不扫描 `.agents/skills`，不自行决定规则文件，不直接推进状态。

Runner 设计：

- `manual_submit`
- `direct_llm`
- `acp_agent`

三种 runner 最终都必须走同一条路径：

```text
submitStageDraft -> Artifact Store -> Manifest -> Validator -> Approval
```

审批策略必须可配置：

- 默认来自 pipeline definition。
- 项目覆盖写入 `sceneforge/approval_policy.yaml`。
- `validated != approved`。
- Validator failed 永远不能自动通过。

Stage Skill Pack 是产品内运行时规则包：

- 推荐位置：`prompts/sceneforge/stages/<stage>/`
- 程序读取 system/user/agent instructions、output contract、artifact templates、review checklist。
- 旧 SceneForge Agent skills 只作为迁移素材，不是运行时事实源。

Scene Asset Library 需要迁移有价值的风格与方法资产，但本期明确不迁移 `source-materials`。
