### 1.2 左侧仅 3 个阶段 vs 引擎 13 阶段

- **UI：** `SceneForgeStudio.tsx` 只渲染 `design` / `storyboard` / `video_prompts`（`coreStages` 常量）。
- **引擎：** [`electron/sceneforge/pipeline/scene-stage-definitions.ts`](electron/sceneforge/pipeline/scene-stage-definitions.ts) 定义完整链：

  `source_intake` → `topic_gate` → `reference` → `story` → `assets` → **core 三阶段** → `script` → `performance` → `storyboard`（依赖 design+performance）→ `audio` → `video_prompts` → `publish` → `export`

- **旧 SOP 来源：** `/Users/tangwujun/Documents/trae_projects/scene_forge/.agents/skills`（`scene-forge`、`scene-video-intake`、`scene-topic-gate`、`scene-story-development` 等）；迁移对照见 [D2 Stage Pack 迁移](../../docs/sceneforge/2026-06-17-sceneforge-stage-pack-migration-design.md)。

**用户期望：**

- 侧栏 **全流水线可见**（分组：前期 / 制作 / 交付）。
- **人工确认可配置**：已有 `approval_policy`（required / optional / auto_if_valid / skip），与 runner（manual / direct_llm / acp）并列展示。
- 两条典型入口路径：**选题/改编/故事**（`topic_gate` 起） vs **先解析视频**（`source_intake` / video-intake）。

### 1.3 交互缺失 → 无法端到端 HITL 测试

| 能力 | 现状 |
| --- | --- |
| 用户输入（文本/链接/视频） | Studio 无 intake / gate 工作区 |
| AI 方案 + **用户确认**（风格、改编方向、go/observe/drop） | `topic_gate` 无确认卡片 UI；逻辑在旧 skill，未产品化 |
| 支撑阶段 submit / validate / run | Validator 与批量 submit 以 **core 三阶段** 为主；支撑阶段无 pack / 无 Studio 工作区 |
| `acp_agent` | MVP 为 briefing（`__acp_session_brief`），非完整 ACP 会话循环 |

**结论：** Phase 2 交付的是 **技术底座 + core 三阶段闭环**（context、handoff、P0 pack、runner、`StageRunPanel`），**不等于** 旧 SceneForge 可产品化全流程。Issue 20「Electron 点跑」在 core 上可试，但用户阻塞项在 **全链可见 + 前期确认 + 支撑阶段最小可跑**。
