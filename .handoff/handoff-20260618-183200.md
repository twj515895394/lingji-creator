## 0. 给下一代理的第一件事（阻塞项）

### 0.1 continue-run 与能力表不同步（测试会红）

**现象：** `tests/sceneforge-continue-run.test.ts` 期望 `script`（及 `design → script` 边界）支持 `direct_llm`；工作区 **`src/sceneforge/lib/scene-stage-run-capabilities.ts` 第 26 行仍为 `MANUAL_ONLY`**，与 Support Pack / 测试意图不一致。

**已准备好的修复（勿手抄逻辑，直接覆盖文件）：**

| 源（补丁） | 目标 |
| --- | --- |
| `.scratch/patches/scene-stage-run-capabilities.ts` | `src/sceneforge/lib/scene-stage-run-capabilities.ts` |
| `.scratch/patches/scene-continue-run.ts` | `src/sceneforge/lib/scene-continue-run.ts` |

一键脚本（维护者在 **Terminal.app** 执行，不依赖 Agent 写 `src/`）：

```bash
cd ~/Documents/trae_projects/lingji-creator
bash .scratch/patches/apply-continue-run-fix.sh
npx vitest run tests/sceneforge-continue-run.test.ts
```

根因说明：`.scratch/fix-continue-run-design-boundary.md`

**注意：** `getStageSupportedRunners` 在 `src` 里若已委托 `getSceneStageRunCapability`，**只改能力表一行**也可能够；但以补丁两份为准最省事。

### 0.2 Agent 写盘权限（用户已多次受挫）

**事实（本会话与延续会话一致）：**

- 对 `Documents/trae_projects/lingji-creator` 下 **`src/`、`tests/`、`electron/`** 等路径，Claude **桌面端** 内 Agent 的 `Read`/`Write`/`Edit` 常报 **`EPERM: operation not permitted`**，即使用户点了目录授权（`mcp__ccd_directory__request_directory` 显示 granted）。
- **`.scratch/`、`.handoff/`、`prompts/`** 往往可写；**`src/` 常不可**——这是**会话/沙箱策略**，不是补丁没写好。
- 同机 **Terminal.app 里 `cd` 到仓库后 `claude`**，或 **桌面端新开会话 + 以文件夹打开整仓**，通常能正常改 `src/`（用户需自行验证）。

**下一代理禁止：**

- 让用户「复制 `.scratch/patches` 进 `src`」当默认方案。
- 在已确认 EPERM 的旧桌面会话里反复 `Edit src/...` 浪费轮次。

**下一代理应做：**

1. 先 `Write`/`Read` 探针一个小文件如 `src/sceneforge/lib/scene-continue-run.ts`；若 EPERM → 明确告知用户用 **CLI 或新会话**，并给出上面 `apply-continue-run-fix.sh`。
2. 用户本地跑完 vitest 后，根据输出继续排错（可在能写 `src` 的会话里接棒）。
