### 1. `P1` 最近项目在部分 Remix 打开路径下不会立即持久化精确落点

状态：**已在本轮修复**

定位：

- [src/lib/remix-app-session.ts](/Users/tangwujun/Documents/trae_projects/lingji-creator/src/lib/remix-app-session.ts:100)
- [src/App.tsx](/Users/tangwujun/Documents/trae_projects/lingji-creator/src/App.tsx:506)
- [src/lib/recent-project-identity.ts](/Users/tangwujun/Documents/trae_projects/lingji-creator/src/lib/recent-project-identity.ts:53)

现象：

- `openProject()` 在 SceneForge 工程走 Remix 路由打开时，会先用 `buildRecentProjectIdentityForOpen()` 把最近项目写盘
- 但 `buildRecentProjectIdentityForOpen()` 在 `options.remixRoute` 存在时把 `remixRoutePath` 固定写成了 `null`
- 只有后续页面状态 effect 再跑一轮 `resolveRemixRecentProjectIdentity()`，最近项目里的精确路由才会被补写回来

风险：

- 如果用户在这次“先写 recent -> 再补 route”的窗口期内退出应用，最近项目只会留下 `projectKind=remix` 和 `entryIntent`
- 下次打开会退化到 `/remix/assets`，丢失“处理中队列 / 失败详情 / creation workspace”这类精确落点

建议修复方向：

- `buildRecentProjectIdentityForOpen()` 在 `options.remixRoute` 存在时，直接写入 `buildRemixPath(options.remixRoute)`
- 补一个 recent project reopen 回归测试，覆盖 processing / details / creation 三种路径

本轮实际修复：

- 已将 [src/lib/remix-app-session.ts](/Users/tangwujun/Documents/trae_projects/lingji-creator/src/lib/remix-app-session.ts) 中 `buildRecentProjectIdentityForOpen()` 的 `remixRoutePath` 从 `null` 改为直接持久化 `buildRemixPath(options.remixRoute)`
- 现在 SceneForge 工程以 Remix 路由打开时，最近项目会在首次写盘时就携带精确落点，而不是依赖后续页面 effect 二次补写
- 已更新测试：
  - [tests/remix-app-session.test.ts](/Users/tangwujun/Documents/trae_projects/lingji-creator/tests/remix-app-session.test.ts)

修复后预期行为：

2. 处理中素材 -> 中途退出 -> 返回资产库 -> 再次打开 -> 恢复到正确处理上下文
3. 失败素材 -> 异常队列 -> 查看失败原因 -> 重跑 -> 恢复正常处理
