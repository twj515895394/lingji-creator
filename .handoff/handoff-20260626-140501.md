## 本轮调研与关键判断

### 1. `transnetv2Pro` 只能作为参考，不建议整库接入

本轮查看了：

```text
https://github.com/antcloudsman/transnetv2Pro
```

结论：

*   它的 CLI 处理链路有参考价值：视频校验、ffprobe 获取信息、ffmpeg 抽 `48x27 RGB` 帧、TransNetV2 推理、predictions 转 scenes、可视化和视频切割。
*   可参考其中的 PyTorch 推理、帧提取、动态阈值、短场景合并和视频切割思路。
*   不建议整库接入，因为它包含 PyQt5、FastAPI、uvicorn、matplotlib 等较重依赖；本项目已有 Electron/React UI，不需要额外 GUI/API 框架。
*   其 FastAPI 部分更像任务壳或模拟流程，不适合作为本项目真实后端服务直接复用。
*   授权信息仍需谨慎核验，不能直接复制大段代码进入项目。

### 2. Hugging Face 现成 PyTorch 版 TransNetV2 更适合作为模型资产来源

用户补充了：

```text
https://huggingface.co/magnusdtd/TransNetV2/tree/main
```

本轮设计中已将其作为推荐模型来源之一。

关键判断：

*   如果该 Hugging Face 仓库已经提供 PyTorch 模型结构代码和 `.pth` 权重，则优先使用它。
*   不需要再从官方 TensorFlow 权重手动转换 PyTorch 权重。
*   不能只准备 `transnetv2-pytorch-weights.pth`；`.pth` 只是权重文件，还必须有匹配的 PyTorch 模型结构代码。
*   代码里不要强依赖文件名一定叫 `transnetv2-pytorch-weights.pth`，应支持环境变量和目录扫描。

## 需要特别注意的设计约束

### 1. `source_clip.mp4` 是一等产物

分镜切片不再只是生成时间边界。每个 segment 都必须生成真实视频片段：

```text
sceneforge/remix/source-assets/{sourceAssetId}/source_segments/{segmentId}/source_clip.mp4
```

该片段应可以直接用于 Seedance 2.0、外部视频编辑、素材库复用。

### 2. 自动切片和人工校准必须同步 clips

以下操作都需要重新生成片段：

*   自动重跑切片。
*   人工合并当前段与下一段。
*   在当前播放点拆分。
*   未来的手工边界调整。

第一版可全量重生成，第二版再做增量缓存。

### 3. 检测边界和工程拆分不能混淆

TransNetV2 / PySceneDetect 输出真实分镜边界；为了下游模型帧数限制而做的长镜头拆分属于工程拆分。两者来源要分别记录：

```text
transnetv2_single_frame
pyscenedetect_adaptive
max_duration_split
manual_override
```

### 4. `.pth` 不是完整模型

高精模式至少需要：

```text
.pth 权重文件
+ PyTorch 模型结构代码
+ torch/numpy 等依赖
```

不能只把 `transnetv2-pytorch-weights.pth` 放进去就认为可以运行。

### 5. Hugging Face 模型代码不要直接用 CLI 作为最终接口

即使 Hugging Face 仓库提供 `main.py`，本项目也应在自己的 Python Worker 中调用模型代码，统一输出 `ShotDetectionResult JSON`，避免外部 CLI 输出格式不稳定。

### 6. 权重文件不要直接进普通 Git

开发期推荐：

```text
LINGJI_TRANSNETV2_MODEL_PATH=/absolute/path/to/model.pth
```

正式发布再考虑：

*   Git LFS。
*   安装包内置。
*   首次启动下载。
