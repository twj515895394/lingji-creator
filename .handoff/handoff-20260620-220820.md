# SceneForge rhythm contract 收口交接

## 一句话状态

`design -> script -> storyboard` 的节奏 contract 已在代码、prompt、validator 和回归测试层面收口完成；当前只剩人工真机验收与结果回填。

## 本轮完成

### 1. design 阶段补齐项目级 rhythm contract

- 位置：
  - `electron/sceneforge/validators/validators.design.ts`
  - `prompts/sceneforge/stages/design/`
- 已要求并校验：
  - `rhythm_contract`
  - `segment_rhythm_profiles`
  - `cut_density_expectation`
  - `boundary_rules`
- 关键约束：
  - 必须给出 `segment_duration_seconds`
  - 必须给出按段长分档的镜头密度预期
  - 必须给出“不跨段”的 boundary 规则

### 2. script 阶段补齐 pacing handoff

- 位置：
  - `electron/sceneforge/validators/semantic-support-stages.ts`
  - `prompts/sceneforge/stages/script/`
  - `src/sceneforge/lib/scene-prep-support-stages.ts`
- 已要求并校验：
  - `segment_strategy` 必须带段长与时间区间
  - `video_generation_unit_plan` 必须带 `pacing_profile` / `shot_density_hint`
  - `storyboard_handoff` 必须带 `boundary_lock`
- 已拦截：
  - beat/段落空壳
  - pacing handoff 过薄
  - `10s` 分段下出现 `9-13s` 这类跨段区间

### 3. storyboard 阶段补齐 shot density / boundary enforcement

- 位置：
  - `electron/sceneforge/validators/validators.storyboard.ts`
  - `prompts/sceneforge/stages/storyboard/`
- 现要求 `storyboard_prompt_pack_plan` 显式给出：
  - `segment_duration_seconds`
  - 每段 `time_range / pacing_profile / shot_count / boundary_lock`
- 当前镜头密度硬规则：
  - `5s`: `3-8`
  - `6s`: `4-9`
  - `8s`: `5-10`
  - `10s`: `6-12`
  - `15s`: `8-16`
- 同时按 `lyrical / balanced / kinetic` 做更细分的节奏窗口校验。

### 4. 已修真实失败样例

- 现象：`script` 阶段真实草案里已有 `story_beats`，仍报“至少应给出 3 个以上 beat，并明确 beat_id”
- 根因：旧解析逻辑过窄，只接受有限格式，没覆盖真实草案里的 `- **beat_01: 标题**`
- 修复：扩展 `semantic-support-stages.ts` 的 section / beat 解析规则，并补充回归测试
- 状态：本地已修复，待你用真机链路再确认一次

### 5. 已修运行面板的“撤回并重生成”假动作

- 现象：已提交阶段点击 `撤回并重生成`，确认后只显示“已撤回本轮确认”，但不会真正触发新一轮生成，看起来像假功能
- 根因：`StageRunPanel` 原实现只调用 `sceneRequestRevision` 撤回阶段状态，并未继续调用 `sceneRunStage`
- 修复：确认撤回成功后，立即串行触发一次 fresh run，真正回到“撤回后立刻重生成”的用户语义
- 当前语义：
  - 已提交产物不会被静默删除
  - 阶段状态先回到 `revision_requested`
  - 随后自动发起一次新的草案生成
  - 新草案仍需再次提交、校验、审批
