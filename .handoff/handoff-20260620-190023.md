### 3. “本阶段输入”语义修复

- 已确认当前引擎真实逻辑：
  - 只要出现在 `stageContext.requiredInputs` 或 `stageContext.optionalInputs` 里，并且已就绪，就都会进入 prompt。
  - 区别不在“会不会发给模型”，而在“是否阻塞运行”。
- UI 文案已从“必需 / 可选”调整为：
  - `阻塞型上游输入`
  - `补充型上游输入`
- 并明确说明：
  - 阻塞型：缺失会阻止运行；已就绪时也会发给模型。
  - 补充型：不阻止运行；只要存在，也会一并发给模型。
- 这里只改了“语义解释层”，没有改底层 context builder / prompt renderer 的行为。
- 相关文件：
