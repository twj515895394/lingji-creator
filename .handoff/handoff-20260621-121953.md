## 用户报告事故：「所有阶段状态都没有了」

### 现象（用户描述）

- 此前多阶段 **已完成**（approved / completed 等），整改后 Studio **侧栏/流水线显示像全部未做** 或状态不对。

### 尚未在本会话验证

- 未对用户指定项目目录做 `state.json` / `artifact_manifest.yaml` / `project.json` 的 **前后对比**（用户未在本 handoff 对话中给出路径；上一轮 handoff 曾出现 `/Users/tangwujun/Documents/test/test003`）。

### 高优先级怀疑点（接手代理必须逐项排除）

1. **`readSceneState` 自动写盘**  
   打开项目即触发迁移写回。若 `normalizeSceneState` 对旧 `stages` 键名处理有误，可能 **覆盖** 磁盘上原有 `approved` 等状态。  
   **动作：** 找 Time Machine / git 外备份 / `state.json.bak`；对比写回前后 `stages.*.status`、`artifactIds`、`validatedAt`。

2. **补全缺失阶段 = `ready`**  
   旧 `state.json` 若只持久化了 **部分阶段**（历史实现可能未写全 12 键），normalize 后为缺键补 `ready`。**不应**覆盖已有键，但 UI 会显示 **大量 ready**，用户体感像「全没了」。  
   **动作：** 确认已完成阶段键是否仍在文件中为 `approved`/`completed`；若文件对、UI 错 → 查 `getProjectState` / `SceneForgeStudio` 的 `buildScenePipelineGroups`。

3. **`export` → `publish` 合并**  
   若同时存在 `stages.export` 与 `stages.publish`，会 `mergeStageRuntimeState`。一般应保留较高 rank 状态；若 publish 曾为 ready 而 export 为 validated，合并后应为 validated。若用户只有 export 无 publish，迁移后应保留 export 状态。  
   **动作：** 查是否误把 **artifactIds** 从 `export.final_prompt_pack` 留在 publish 上导致校验/展示异常。

4. **`currentStage` 被改为 `publish`**  
   用户可能以为「当前阶段」跳到最后，**已完成标记** 若依赖 currentStage 逻辑可能误导（需读 `getRecommendedResumeStage`）。

5. **`project.json` 与 `sceneforge/state.json` 双写不同步**  
   `readSceneProjectMeta` 读 `project.json` 的 `sceneforge` 段；运行时状态以 **`sceneforge/state.json`** 为主（`getProjectState` → `readSceneState`）。若只修了 meta 未修 state 或反之，会出现不一致。

6. **artifact manifest 仍在、state 被重置**  
   产物文件在磁盘上但 `stages.*.artifactIds` 空 → UI 可能显示未提交。  
   **动作：** `listSceneArtifacts` vs `state.stages[*].artifactIds` 交叉核对。

7. **MCP / 旧文档仍写 `export` 阶段枚举**  
   部分工具 schema 可能仍含 `export`（需 `grep`）；可能导致外部脚本写坏 state（低概率但应扫）。

### 建议修复方向（不在此 handoff 内实施）

- **数据恢复：** 从备份恢复 `sceneforge/state.json`；或写 **一次性修复脚本**：根据 `artifact_manifest.yaml` 反推各阶段 `draft_submitted` / `approved`（需严格对照 stage→artifact 映射，见 `scene-stage-definitions` / store）。
- **迁移安全：** 写回前 **备份** `state.json` → `state.json.pre-export-migration`；或仅在用户确认后 persist。
- **normalize 策略：** 缺键补 `ready` 是否应改为「仅从 manifest 推断」——产品决策。
- **验收：** 固定一个 **真实项目路径** 做 before/after 截图 + JSON diff，写入 `progress.md` 或 issue。
