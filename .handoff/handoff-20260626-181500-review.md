## 二、P0 / 高优先级问题

### P0-1：`regenerateSourceSegmentClips()` 会删除已抽取的关键帧

涉及文件：

```text
electron/sceneforge/remix/segment-clips/segment-clip-maintenance.ts
electron/sceneforge/remix/remix-segmentation-service.ts
```

问题位置：

```ts
regenerateSourceSegmentClips()
  → writeSegmentArtifacts()
```

而 `writeSegmentArtifacts()` 当前会先执行：

```ts
fs.rm(getRemixSourceSegmentsDir(sourceAssetId), { recursive: true, force: true })
```

这会删除整个：

```text
source_segments/
```

包含：

```text
segment_manifest.json
source_clip.mp4
first_frame.png
middle_frame.png
last_frame.png
```

风险：

```text
用户点击 Phase 3 的“重新生成片段”后，如果 Phase 4 已经生成过关键帧，会把关键帧图片一起删除。
但 regenerateSourceSegmentClips 只重新生成 clips，不会重新抽关键帧。
最终 document 里仍保留 keyframe 路径，但文件已经不存在，media validation / KeyframeGallery 可能失败。
```

建议修复：

```text
新增 clip-only regeneration：
  regenerateSourceSegmentClips()
    → 只重建 source_clip.mp4
    → 不删除 source_segments/{segmentId}/ 下的 keyframe png
    → 不覆盖 segment_manifest.json 之外的文件

或者：
  writeSegmentArtifacts 增加选项：preserveKeyframes: true
```

建议优先级：必须先修，再进入人工测试。

### P0-2：前端 `SegmentClipActionsPanel` 可能存在 `window.electronAPI` 全局类型缺口

涉及文件：

```text
src/sceneforge/remix/components/SegmentClipActionsPanel.tsx
src/sceneforge/remix/segment-clip-api.d.ts
src/lib/electron-api.ts
```

当前 `SegmentClipActionsPanel` 使用：

```ts
window.electronAPI?.showItemInFolder?.(...)
```

同时新增的 `segment-clip-api.d.ts` 只声明了：

```ts
window.sceneForgeRemixSegmentClips
```

review 过程中未在已查看文件里确认 `window.electronAPI` 的全局声明。虽然 `src/lib/electron-api.ts` 定义了 `ElectronAPI` interface，并且项目既有 preload 会暴露 `electronAPI`，但是否有全局 `Window.electronAPI` 类型声明需要 `tsc` 验证。

风险：

```text
npx tsc --noEmit 可能报：Property 'electronAPI' does not exist on type Window。
```

建议修复：

```text
在 segment-clip-api.d.ts 或现有全局声明文件中补：

import type { ElectronAPI } from '../../lib/electron-api';

declare global {
  interface Window {
    electronAPI?: ElectronAPI;
    sceneForgeRemixSegmentClips?: RemixSegmentClipApi;
  }
}
```

或在组件内部改为：

```ts
const electronApi = (globalThis as { electronAPI?: ElectronAPI }).electronAPI;
```

建议优先级：先跑 tsc；若报错立即修。

## 三、P1 / 中高优先级问题

### P1-1：构建期字符串注入 UI / preload，维护风险较高

涉及文件：

```text
electron.vite.config.ts
src/sceneforge/remix/components/SegmentClipActionsPanel.tsx
electron/sceneforge/remix/segment-clips/segment-clip-preload.ts
```

当前为了避免大文件替换，采用 Vite transform：

```text
injectRemixSegmentClipPreloadPlugin
injectRemixSegmentClipActionsPanelPlugin
```

风险：

```text
1. RemixAssetProcessing.tsx 源码里看不到 SegmentClipActionsPanel，后续维护者容易漏掉。
2. 插入依赖精确字符串：
   import { SegmentTimeline } from '../components/SegmentTimeline';
   和
   '        <SegmentTimeline\n'
   页面结构稍微变动，注入就会静默失效。
3. 单测/静态分析看不到真实源码结构，UI 行为更依赖构建过程。
```

建议修复：

```text
短期：在 handoff/README 中明确这是临时注入。
中期：直接修改 RemixAssetProcessing.tsx 源码，显式 import + 渲染 SegmentClipActionsPanel。
长期：把 segment clip 操作并入标准 RemixIpcContract / electronAPI.sceneForgeRemix，而不是额外挂 window.sceneForgeRemixSegmentClips。
```

### P1-2：debug 报告写入失败会影响主流程

涉及文件：

```text
electron/sceneforge/remix/remix-debug-artifacts.ts
electron/sceneforge/remix/remix-segmentation-service.ts
electron/sceneforge/remix/remix-keyframe-service.ts
```

当前 `writeRemixDebugJson()` 失败会直接抛错。

风险：

```text
切片/关键帧主产物已经生成成功，但 debug JSON 或 progress_events.jsonl 写入失败时，整个阶段仍会失败。
```

建议修复：

```text
把 debug 写入降级为 best-effort：
  try writeRemixDebugJson
  catch error → append warning 到 diagnostics 或 console，不阻断主流程
```

尤其是：

```text
shot_detection_result.json
clip_generation_report.json
keyframe_report.json
runtime_diagnostics.json
progress_events.jsonl
```

这些应服务于排查，不应该比主产物更关键。

### P1-3：clip 生成失败时没有失败版 `clip_generation_report.json`

涉及文件：

```text
electron/sceneforge/remix/remix-segmentation-service.ts
electron/sceneforge/remix/segment-clips/segment-clip-service.ts
```

当前流程：

```text
SegmentClipService.generateClips()
  → 有任意 failed 就 throw
  → writeSegmentArtifacts() 后续才写 clip_generation_report.json
```

风险：

```text
如果 ffmpeg 对某个片段失败，正好最需要 debug report，但 report 不会写出。
```

建议修复：

```text
SegmentClipService.generateClips() 不应直接丢失 failed results。
可以返回 summary 并由调用方决定是否 throw，或者抛出带 summary 的自定义 Error。
writeSegmentArtifacts() 应在失败时也写 clip_generation_report.json。
```

### P1-4：关键帧抽取失败时没有失败版 `keyframe_report.json`

涉及文件：

```text
electron/sceneforge/remix/remix-keyframe-service.ts
```

当前逻辑：

```text
某张关键帧失败
  → 直接 throw
  → 只有成功项在内存 reportItems
  → keyframe_report.json 不会写出
```

风险：

```text
排查失败时，只能看 job error，缺少已成功/失败的逐帧上下文。
```

建议修复：

```text
reportItems 支持 status: ready | failed
失败时先写 keyframe_report.json，再抛出包含 segmentId/frameRole 的错误。
```

### P1-5：TransNetV2 accurate worker 目前是通用适配层，尚未针对真实 HF 代码验证

涉及文件：

```text
resources/shot-detectors/accurate_transnetv2.py
resources/shot-detectors/README.md
```

当前实现假设：

```text
1. vendor 目录中存在可直接 import 的模块名：
   transnetv2_pytorch / transnetv2 / model / models / net / nets / network

2. 模型类可无参构造：
   model = model_class()

3. .pth 可通过 load_state_dict 加载。

4. model(tensor) 输出可从 dict/tuple/list/tensor 中通用解析。
```

风险：

```text
Hugging Face magnusdtd/TransNetV2 的真实文件名、类名、构造函数、输出结构可能与这些假设不完全一致。
```

建议修复：

```text
拿到实际 HF 文件后补专用 adapter，例如：
  hf_magnusdtd_adapter.py
或在 accurate_transnetv2.py 中增加明确的 module/class mapping。

并增加 smoke-load：
  import model
  torch.load weights
  load_state_dict
  dummy forward
```

### P1-6：TransNetV2 worker 会一次性把整段视频帧读入内存

涉及文件：

```text
resources/shot-detectors/accurate_transnetv2.py
```

当前逻辑：

```python
frames = []
while capture.read():
    frames.append(resized_rgb)
np.stack(frames)
model(tensor)
```

风险：

```text
长视频会占用大量内存；如果后续模型内部还做时序卷积/窗口处理，OOM 风险更高。
```

建议修复：

```text
按 TransNetV2 官方/模型实现要求做 sliding window / batch window 推理。
至少增加：
  maxFrames guard
  friendly error
  fallback fast
```
