## 已完成内容

### 1. 替换占位 PNG 逻辑

更新：

```text
electron/sceneforge/remix/remix-keyframe-service.ts
commit: c9d5e59e1b155b0b456e2e80498edc93f389cb22
```

移除旧逻辑：

```text
ONE_PIXEL_PNG
fs.writeFile(filePath, ONE_PIXEL_PNG)
```

改为真实 ffmpeg 抽帧。

### 2. 每段固定生成三张关键帧

当前每个 segment 都生成：

```text
first_frame.png
middle_frame.png
last_frame.png
```

对应角色：

```text
first
middle
last
```

不再只给长片段生成 middle。

### 3. 抽帧输入源策略

当前逻辑：

```text
如果 source_clip.mp4 存在：
  从 source_clip.mp4 抽帧，使用片段内相对时间

如果 source_clip.mp4 不存在：
  从原 sourceVideoPath 抽帧，使用原片绝对时间
```

目的：

```text
1. 优先保证关键帧与真实分镜片段 source_clip.mp4 对齐。
2. 如果旧项目还没有 clip，也能回退到原片抽帧。
```

### 4. 时间点安全偏移

为避免直接抽在 0ms 或片段最后一帧导致 ffmpeg 失败，当前策略：

```text
first：startMs + safe offset
middle：(startMs + endMs) / 2
last：endMs - safe offset
```

短片段会自动 clamp，避免越界。

### 5. ffmpeg 解析

使用项目已有：

```text
resolveFfmpegPath()
```

找不到内置 ffmpeg 时回退：

```text
ffmpeg
```

即使用系统 PATH 里的 ffmpeg。

### 6. 错误处理

如果 ffmpeg 失败或输出 PNG 为空，会抛出包含 segment 与 frameRole 的错误，例如：

```text
关键帧抽取失败：segment-001/first (clip) - xxx
```

这会让 `runSourceKeyframes` 任务进入失败态，便于用户从失败队列重试。
