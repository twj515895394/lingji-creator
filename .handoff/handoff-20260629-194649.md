## 功能模型（与 170233 一致，仅补决策结论）

原片理解 = **ASR/transcript** + **segment understanding（LLM + frame vision）** + **original story rollup**。  
**产品铁律（用户确认 + 已写进文档）**：台词纠偏 / 重跑 ASR **不**使画面理解与 video prompt 过期，**不**提示「台词已修改请重跑理解」。

理解过期仅与：关键帧/片段时间范围、frame vision 更新、缺失 analysis 等相关。

## 本轮及近期已落地修改（按主题）

### 1. 台词与画面理解解耦

- **问题**：改台词或确认台词后，workbench 仍提示理解过期或清空 analysis（体验与产品语义不符）。
- **方案**：见 [transcript-understanding-decoupling.md](../docs/sceneforge-remix/transcript-understanding-decoupling.md)。
- **实现要点**：
  - `buildSegmentUnderstandingInputHash` 不再含 `transcriptPlainText`；`segmentUnderstandingInputHashMatchesStored` 兼容旧 hash。
  - `RemixTranscriptCorrectionService` 移除 major 修改时清空 understanding。
  - workbench / freshness 不再因 `transcript_correction_changed` 标 stale。
- **提交线索**：`6a942e2 fix(remix): decouple transcript edits from visual understanding stale`

### 2. Video prompt 多维度 + 对白/口型

- **问题**：UI `dimensions[]` 常空；对白弱、未体现说话/口型。
- **方案**：从 `RemixChineseVideoPrompt` 14 个 `*Prompt` 字段合成 `dimensions[]`；归一化时注入 dialogue/performance 提示。
- **关键文件**：`remix-segment-understanding-schema.ts`、`remix-understanding-workbench.ts`
- **测试**：`tests/sceneforge-remix-video-prompt-dimensions.test.ts`
- **提交线索**：`4850e41 feat(remix): enrich video prompt dimensions and dialogue from transcript`

### 3. 烧录字幕权威（对白优先级）

- **决策顺序**：画面硬字幕 > 人工校对台词 > ASR。
- **实现**：frame vision 抽取 `onScreenSubtitles`；`remix-on-screen-subtitle.ts`；`buildSegmentUserPrompt` 增加【画面烧录字幕（权威）】块。
- **注意**：旧 `frame_vision.json` 无该字段时需**重跑 frame vision**，仅重跑理解读不到字幕。
- **提交线索**：`5dc7072` + mock 修复 `25b6a95`

### 4. Issue 06 / 07（批次 B 部分）

- **06 ASR 双箭头**：`remixSelectSkin`，避免 `Select` 内置 Chevron + `.customSelect` 背景图双箭头。
- **07 重跑本段理解**：Dialog + `understandingRerunHint`（一次性，不写盘）；IPC `SegmentKeyframeActionInput.understandingRerunHint`。
- **提交线索**：`609a5af feat(remix): fix ASR select chevron and segment understanding rerun hint`

### 5. 「一键确认所有片段台词」无反应（本轮用户反馈 + 修复）

- **现象**：无异常时点击按钮，左侧阶段不变、不跳转下一步，像没反应；多数**不是**后端抛错被吞，而是前后端契约与阶段机未接完。
- **根因**：
  1. IPC 只返回 `RemixUnderstandingWorkbenchSnapshot`，`runAction` 期望 `RemixAssetProcessingSnapshot` → `applySnapshot(undefined)`，阶段 UI 不更新。
  2. 后端从未把 `remix_understanding` 设为 `approved`（生成后多为 `ready_for_review` / `needs_input`）。
  3. 成功路径未 `setActiveStepId('annotate')`。
- **方案**：
  - 新增 `remix-understanding-approval.ts`：`evaluateRemixUnderstandingApproval`（产物 gate + freshness + 各段台词 confirmed）。
  - `RemixService.confirmAllSegmentTranscripts`：确认落盘 → 评估 → 写 `remix_understanding: approved` → 返回 snapshot。
  - 前端：刷新 workbench + 自动进入「人工标注」；失败则 `setErrorMessage` 显示 blockers。
  - stale 横幅文案去掉「台词更新导致过期」（与解耦一致）。
- **状态**：实现于工作区；撰写 handoff 时**可能尚未 commit**（见 `git status`）。
- **测试**：`tests/sceneforge-remix-understanding-approval.test.ts`；`sceneforge-remix-asset-processing.test.tsx` mock 已改为返回 snapshot。

### 6. 继承自 170233 的已修项（会话前/中已合入）

## 未完成 / 待优化

### 高优先级（产品可感知）

1. **提交并真机验收**「一键确认 → 原片理解已完成 → 跳转人工标注」；失败文案是否清晰。
2. **Issue 04 语义补全**：除阶段 `approved` 外，确认后 workbench 是否仍有假 stale 提示（解耦后应主要剩 vision/keyframes 类）。
3. **Issue 10**：原片理解区「台词动作 / 理解动作」分组与组合回归（HITL）。

### 中优先级

4. **存量 frame vision**：无 `onScreenSubtitles` 的工程需引导或批量重跑 vision。
5. **人工补字幕入口**（若 vision 识别不到硬字幕）— 未设计。
6. **`evaluateRemixUnderstandingApproval` 与 `validateRemixUnderstandingArtifacts`**：门禁较严，占位/rollup 不完整时一键确认会报错——需与产品确认是否允许「仅确认台词、阶段仍待确认」的分态（当前实现为：须同时满足才可 approved）。

### 低优先级 / 已废止或降级

7. **Issue 08/09 台词分层 stale**：产品已选**完全解耦**，勿再实现「轻微纠偏不失效、major 失效」除非用户重新开设计。
8. **理解区动作过多**：rollup / stale segment / 全量 ASR / 生成理解 / 一键确认同屏——待 Issue 10 信息架构。
9. **用户补充 hint 持久化**：当前一次性；有复用需求再扩 segment note。
