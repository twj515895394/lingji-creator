## 当前流水线与产品命名（实现真相）

### 用户可见名 vs 技术名

| 文档早期表述 | 当前约定 |
|--------------|----------|
| SceneForge Prompt Pack Project | 项目 `type: sceneforge`；用户可见 **视频内容创作工坊**（ADR-0001） |
| 一级交付「Prompt Pack 导出」 | **已移除**独立 export 阶段与文件夹/ZIP 导出 IPC |
| MVP 末尾 `Export Prompt Pack` | 末尾为 **`publish`（发布说明）** + **「完成创作」全项目收工** |

### 12 阶段顺序（`SCENE_STAGE_IDS`）

```text
source_intake → topic_gate → reference → story → assets
→ design → script → performance → storyboard → audio
→ video_prompts → publish
```

- **Core（须 approved 才能算流水线核心完成）**：`design`、`storyboard`、`video_prompts`
- **交付末阶段**：`publish`（产物 `publish_notes`，5 个 copy-block）
- **退役阶段**：`export`（仅 legacy 迁移；见 `scene-state-machine.ts`、`scene-artifact-store.ts`）

### 项目级完成语义（本会话新增）

- `sceneforge/state.json` → `status: 'completed'`（全项目收工后）
- `project.json.sceneforge.status` 经 `syncSceneProjectMetaFromState` 同步
- 触发：发布说明阶段 **Validate 通过** 后点 **「完成创作」** → `sceneforge:complete-project`
- 逻辑：`scene-pipeline-completion.ts`（阶段状态审计 + 各阶段 Validator 重跑）→ `completeSceneForgeProject`

## 架构固定 — 后续请勿轻易动的边界

1. **阶段列表**与 `scene-stage-definitions` / `SCENE_STAGE_IDS` 同步机制。

3. **IPC 三件套**：`electron/main.ts` / `preload.ts` / `src/lib/electron-api.ts`。  
4. **Validator 规则**：除非产品明确改契约，否则优先 **UI 提示** 引导用户重跑 LLM，而非删规则。  
5. **Remotion / 时间线 / TTS**：SceneForge 不嵌入 Cut 主链路（`CLAUDE.md`）。
